# Сборщик Авито: отдельный маршрут и небольшие порции

Для мониторинга чужих публичных объявлений используется отдельный HTTP-сборщик. Ключи Авито для собственных объявлений ему не нужны.

## Что установлено

`mac-price-radar-avito.timer` запускает worker каждый час на dev. Теперь по умолчанию до 60 запросов за запуск, один запрос каждые 10 секунд, без параллельного обхода. Worker проверяет первую страницу выдачи, продвигается по одной сохранённой странице пагинации и обходит свежие/давно не проверенные карточки. Даты цен меняются только после нового ответа карточки. Постраничный обход всегда считается частичным, если полная выдача не подтверждена в этом запуске.

Собственная анонимная сессия хранится в закрытом `session.json`, привязана к адресу маршрута и User-Agent. Браузерные и аккаунтные cookies не импортируются. Смена прокси начинает новую сессию, а пауза старого маршрута остаётся в `access.json`. Прокси используется только этим worker; другие магазины и сайт не затрагиваются.

## Подключение российского прокси

На dev создать `/etc/mac-price-radar/avito-proxy-url` с правами `root:radar 640`; каталог доступен группе radar. Содержимое — одна строка вида `http://user:password@host:port`, `https://...` или `socks5://...`. Специальные символы логина/пароля должны быть URL-encoded. Не помещать секрет в репозиторий, чат, systemd unit или командную строку.

В `/etc/mac-price-radar/avito-dev.env`:

```ini
AVITO_TRANSPORT=http
AVITO_PROXY_URL_FILE=/etc/mac-price-radar/avito-proxy-url
AVITO_INTERVAL_MS=10000
AVITO_MAX_REQUESTS=60
```

После изменения настроек следующий запуск использует прокси. Для первой проверки временно поставить `AVITO_MAX_REQUESTS=3`, запустить сервис и посмотреть результат `/api/status` или `state.json` (второй содержит приватный идентификатор маршрута). Затем вернуть 60 при успешной проверке. HTTP-прокси использует CONNECT для HTTPS Авито; проверка TLS сохраняется. Ошибка прокси не включает прямое соединение.

Адрес прокси проверяется; поддержка SOCKS5 предоставлена закреплённой версией Undici 7.30.0. Внутренние ошибки транспорта не выводят URI/пароль. Публичный статус отдаёт только разрешённые поля.

## Российский сервер

Можно запустить тот же Node 24 worker на российском сервере. Для установки нужен конкретный SSH-адрес/alias. На российском узле хранятся сессия, очередь и исходный snapshot; подтверждённые снимки передаются на dev по аутентифицированному каналу. Копирование не меняет даты наблюдений. Такой удалённый запуск в текущей установке ещё не настроен.

Альтернатива — выделенный прокси, развёрнутый на российском сервере и доступный только dev по закрытому каналу. Не выставлять открытый прокси в Интернет. Из имеющегося лишь адреса сервера автоматически не следует, что на нём уже работает прокси.

## Причины остановки

- `ip_restriction`: Авито сообщил о проблеме с IP.
- `region_restriction`: в ответе явно назван регион/страна или HTTP 451.
- `rate_limit`: HTTP 429 без уточнения IP/проверки.
- `captcha`: ответ требует проверки в браузере.
- `access_denied`: HTTP 403 без доказанной причины.
- `AVITO_NETWORK`: сетевой сбой, включая неработающий прокси.

403/429 не доказывают геоблокировку. После отказа доступа запросы останавливаются; применяется пауза минимум шесть часов, учитывается более длинный Retry-After (до семи суток). Автоматической ротации IP и решения CAPTCHA нет. Российский адрес может помочь при геоограничении, но сам по себе не гарантирует доступ при ограничении частоты или репутации IP.

## Обновление и проверки

Нужны `npm ci --omit=dev --ignore-scripts` по lock-файлу (Undici и Tough Cookie), новые модули `avito-access.mjs`, `avito-transport.mjs`, `avito-batch.mjs`, обновлённые collector/parser/importer. При обновлении сохранять `data/private/avito/` целиком.

```sh
node --test test/avito-access.test.mjs test/avito.test.mjs test/avito-queue.test.mjs
```

Проверены отдельный CONNECT-прокси, отсутствие прямого fallback, сохранение cookies, привязка к маршруту, cooldown, лимит запросов, пагинация порциями, возобновление очереди и защита прежних наблюдений. Доступ через конкретный российский маршрут проверяется отдельно после получения его адреса.

Источники: [Undici ProxyAgent](https://github.com/nodejs/undici/blob/main/docs/docs/api/ProxyAgent.md), [Tough Cookie](https://github.com/salesforce/tough-cookie), [исследование способов в parser_avito](https://github.com/Duff89/parser_avito/blob/master/docs/ANTIBLOCK.md). Сторонний проект описывает мобильные прокси и сервисы cookies; их заявления не являются результатом нашего теста. Чужие cookies/аккаунты и платные сервисы не подключены.
