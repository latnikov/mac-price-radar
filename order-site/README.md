# Макбучная — заказы Mac mini и Mac Studio

Независимый сайт и сервер в существующем репозитории. Не использует API, базу или Telegram-бота парсера цен. Статические HTML/CSS/JS, Node.js 24+, встроенный SQLite; установки пакетов не требуется.

## Состояние запуска — 25.09.2026

Сайт опубликован: https://order.macbookbro.ru . DNS и HTTPS работают, сервис `macbookbro-orders` включён в автозапуск, приём заявок включён. Google-релей установлен в аккаунте владельца с минутным триггером `pollOrderNotifications`. Бот `@macbookbroorders_bot` направляет уведомления в подтверждённый владельцем личный чат. Сквозной тест очереди `MB-RELAY-TEST` доставлен автоматически с первой попытки; тест публичной формы имеет номер `MB-E751D348`. Обе записи явно помечены как тестовые, звонить по ним не нужно.

## Поток заказа

1. Клиент выбирает Mac кнопками и сразу видит предварительную итоговую цену, затем нажимает «Оформить заказ».
2. Вводит российский телефон, при желании имя, подтверждает согласие.
3. POST `/api/orders` повторно проверяет конфигурацию и контакт на сервере, сам определяет актуальную предварительную цену.
4. Сервер сохраняет заявку и очередь уведомлений в одной записи SQLite. Только после сохранения клиент получает номер.
5. В прямом режиме фоновый обработчик отправляет конфигурацию, предварительную цену, телефон и имя в Telegram, повторяя попытки с интервалом до часа. На текущем сервере соединение с Telegram недоступно, поэтому включён режим `ORDER_DELIVERY_MODE=relay`: Google Apps Script примерно раз в минуту забирает очередь по защищённому API и подтверждает успешную отправку. После перезапуска очередь сохраняется.

Отправка Telegram имеет семантику at-least-once: если Telegram принял сообщение, но ответ потерялся, уведомление может повториться с тем же номером заявки. Повторный клик или сетевой retry с тем же ключом не создаёт ещё одну заявку.

## Локальный просмотр

Из корня репозитория: `node order-site/server.mjs`. Адрес: http://127.0.0.1:4180.
Без настроенного получателя и `ORDER_ACCEPTING=1` доступен только просмотр. Не создавать фиктивные успешные заявки.

Проверки: `node --test order-site/test/*.test.mjs`.

## Размещение на существующем сервере

- Код: `/srv/macbookbro-orders` (только файлы этого каталога, без данных, тестов и секретов).
- База: `/var/lib/macbookbro-orders/orders.sqlite`, владелец `radar`, закрытые права.
- Настройки: `/etc/macbookbro-orders.env`, root, режим 0600. Шаблон имён параметров — `deploy/env.example`.
- Сервис: `deploy/macbookbro-orders.service`, отдельный порт 4180 на loopback.
- Caddy для подтверждённого домена: `reverse_proxy 127.0.0.1:4180`. `ORDER_ORIGIN` должен точно совпадать с HTTPS-адресом сайта. Caddy сохраняет Origin; не подменять его настройками из парсера.
- DNS A-запись поддомена должна указывать на `135.106.220.39`; Caddy получает HTTPS-сертификат после появления DNS.
- `ORDER_TRUST_PROXY=1` допустим только с единственным доверенным Caddy перед loopback-сервисом. Сервис не должен слушать внешний интерфейс.
- `ORDER_ACCEPTING=1` включать после проверки чата и доставки тестового уведомления.

## Релей Telegram

`deploy/telegram-orders-relay.gs` — отдельный Google Apps Script, не изменяющий релей парсера. Подготовлен проект: https://script.google.com/home/projects/1eLLu4Eb6uEUcgZ8kkf-WNaLJWaEmn-0gvWw1iQxQpZE5vBZzKLft4WR9/edit . В Script Properties задать `ORDER_API_ORIGIN=https://order.macbookbro.ru` и `ORDER_TELEGRAM_BOT_TOKEN`. На сервере установить `ORDER_DELIVERY_MODE=relay` и подтверждённый `ORDER_TELEGRAM_CHAT_ID`. `ORDER_RELAY_KEY` можно задать отдельно на обеих сторонах (случайные 32 байта или больше); по умолчанию установщик вычисляет SHA-256 от `macbookbro-orders-relay:` + токен бота, как уже настроено на сервере. При смене токена сменить производный ключ на обеих сторонах и удалить старый `ORDER_RELAY_KEY` из Script Properties перед переустановкой. Запустить `installOrderRelay` и разрешить Google выполнение внешних запросов и создание таймера. Развёртывание публичного Google web app не нужно.

API `/api/relay/claim` и `/api/relay/ack` принимают только POST JSON с `Authorization: Bearer <ORDER_RELAY_KEY>`. Один запуск получает до 3 уведомлений с арендой на 3 минуты; потерянная аренда освобождается автоматически. Подтверждение привязано к номеру заявки и одноразовому идентификатору аренды. Google получает текст уведомления и пересылает его в Telegram; клиентская база не копируется в Google Sheets. В журнал не писать текст или токены. Успешные запуски отмечаются в Script Property `ORDER_LAST_SUCCESS`. При длительном отказе смотреть ошибки триггера и серверную очередь.

## Данные и обслуживание

Публичного списка заказов или административного API нет. Секреты и база не раздаются HTTP-сервером. В журнал попадают только номера заявок и общие ошибки, без телефонов и токенов. Заказы нужно архивировать/удалять по принятому магазином сроку хранения; автоматическое удаление пока не настроено. Страница обработки данных описывает фактическую схему; владелец ещё должен предоставить реквизиты оператора и контакт для обращений, чтобы дополнить её.

Резервную копию живой базы делать SQLite backup API (`node:sqlite` `backup`) либо `VACUUM INTO`, а не копированием только основного файла при активном WAL. Нужны регулярные копии на отдельном носителе. Проверка очереди на сервере: `SELECT count(*), min(created_at) FROM orders WHERE notified_at IS NULL;`. HTTP `/healthz` проверяет доступность базы, но не гарантирует доставку Telegram. `/api/status` сообщает, включён ли приём заявок.

Ограничение: до 5 новых заявок с IP за 15 минут (счётчик в памяти сбрасывается при перезапуске), тело до 8 КБ, same-origin JSON, скрытое поле против простых ботов. Это начальная защита; при целевом спаме потребуется challenge или дополнительный лимит на прокси.

## Каталог Apple

Проверено 24.09.2026 по US-конфигураторам:
- https://www.apple.com/shop/buy-mac/mac-mini
- https://www.apple.com/mac-mini/specs/
- https://www.apple.com/shop/buy-mac/mac-studio
- https://www.apple.com/mac-studio/specs/

Mac mini: M6, M5 Pro; Mac Studio: M5 Max, M5 Ultra. Общий публичный контракт `catalog.mjs` задаёт только доступные варианты памяти, накопителя и Ethernet. 512 ГБ памяти Studio объявлены на конец октября и пока не доступны в конфигураторе. Их нет среди отправляемых вариантов. ПО и аксессуары в заказ не включены. Каталог обновляется вручную после сверки Apple; он не является проверкой наличия у поставщиков. Онлайн-оплата отсутствует.

Предварительные цены перенесены из колонки «Итого для покупателя» файла `Новые_Mac_mini_и_Mac_Studio_прайс.xlsx` в закрытый серверный модуль `pricing.mjs`. Рублёвая цена считается как этот итог в USD × (курс Google Finance USD/RUB + 4 ₽) и округляется до целого рубля. На 25.09.2026 в расчёте используется курс Google 84,578 ₽/$, итоговый курс — 88,578 ₽/$. Браузер получает от `/api/quote` только конечную цену в рублях; исходные суммы и составляющие расчёта через сайт не раздаются. При обновлении курса менять `pricingInfo` и заново прогонять тесты.

Заказать можно только конфигурации, для которых в прайсе есть итог: 50 сочетаний. Стандартная начальная конфигурация — Mac mini M6, 16 ГБ памяти и SSD 256 ГБ. Для Mac mini Ethernet фиксирован на 2,5 Гбит/с и в интерфейсе не показывается.
