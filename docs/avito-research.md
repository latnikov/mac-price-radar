Главный вывод: выбор языка или браузера не гарантирует доступ. Свой сервер может быть источником наблюдений для таблицы, но HTTP-доступ, корректность извлечения, полнота выдачи и качество рейтинга проверяются отдельно.

## Реализованный поток

`отдельный worker → выдача → карточки → закрытый snapshot.json → почасовой импорт → SQLite → модель → /api/table → НН (Авито)`

- `scripts/avito-collector.mjs`: отдельный процесс, ограничение размера страниц, частоты, длительности, количества страниц и объявлений. Обычный HTTP-транспорт без обхода защит. Первый HTTP 401/403/429 или CAPTCHA прекращает весь сбор; последующие попытки откладываются на шесть часов. До получения нового среза сохраняется предыдущий.
- `scripts/avito-parser.mjs`: извлечение выдачи из DOM/MFE JSON и карточек из DOM и сериализованной JSON-гидратации. Скрипты объявления не выполняются. Проверены настоящая выдача и одна карточка; остальные варианты разметки ещё требуют проверки. Промо-цена выдачи не подменяет цену из карточки.
- `scripts/avito-policy.mjs`: независимая проверка города, состояния, продавца, конфигурации и полной рублёвой цены. Неясные карточки уходят в review, неподходящие — в excluded. Названия продавцов нормализуются; «Макбучная», «мкбчн» и указанные транслитерации исключаются.
- `scripts/avito.mjs`: читает результат нашего worker с того же сервера. Внешний поставщик JSON не требуется. Возраст среза ≤90 минут, карточки ≤2 часов при импорте. Даты наблюдения не заменяются временем импорта. Причины отсева — в закрытом `review.json`.
- SQLite хранит стабильный ID `avito:<id>` и историю. На полном срезе исчезнувшее объявление получает отдельное наблюдение `Discontinued`; на частичном срезе исчезновение не выводится. Явно неподходящая карточка снимается и при частичном сборе; нераспознанная сохраняет предыдущую цену с низким Trust. Падение покрытия более чем вдвое при минимум десяти прежних карточках требует проверки. Старая цена остаётся в истории.
- `scripts/avito-ranking.mjs`: модель пересчитывается на сервере. API кэшируется с учётом минуты, поэтому возраст продолжает влиять на оценку при остановке сборщика.
- В интерфейсе «НН (Авито)» — группа столбцов по реальному ID профиля продавца. Каждая строка сравнивает одну конфигурацию и цвет; в ячейке минимальная цена данного продавца, ссылка на конкретное объявление, Trust и время проверки. Низкий Trust не скрывает минимальную цену. Другие объявления этой конфигурации раскрываются только внутри ячейки своего продавца. «Аудит цены» содержит исходное название, ориентир, отклонение, диапазон модели, число независимых продавцов, место объявления в рейтинге и причины оценки. Одноимённые профили не объединяются; переименование сохраняет идентичность столбца. При смене фильтров остаются только продавцы выбранной выдачи. До первого среза фиктивных столбцов продавцов нет.
- Совпадение с магазином НН сохраняет отдельные столбцы сайта и профиля Авито; модель при подтверждённом сопоставлении продолжает учитывать их как одного независимого продавца. Средняя НН и рекомендация по сайтам магазинов не подменяются объявлениями.

### Полнота и область поиска

Worker ищет MacBook в категории ноутбуков НН с `localPriority=1`; этот флаг подтверждён в возвращённом состоянии поиска и сохраняется при пагинации. Новое состояние проверяется независимо в каждой карточке. На живой странице найден фильтр `params[110392]`, значение «Новое» — `431235`, но прямые HTML-запросы с этим параметром сервер игнорирует (возвращает пустой `searchCore.params`). Запрос обработчика формы завершился 403. Поэтому серверная фильтрация состояния пока не считается включённой; б/у отсеивается при разборе карточек. Непроверенный непрозрачный `f` не придуман.

На живой выдаче `count` показал 4725, а `totalCount` — 1500: второе число обозначает ограниченную доступную выдачу. После приоритета НН `count` был около 1783, а доступная выдача всё ещё ограничена 1500. Такой обход остаётся частичным; он не подтверждает исчезновение непопавших объявлений и не выдаётся за полный аудит рынка.

Полный срез требует совпадения заявленного количества с числом уникальных ID и разобранных карточек, завершённой пагинации без смены запроса, повторов страниц и изменения общего количества. Публикуются пригодные наблюдения частичного среза, но он не доказывает исчезновение остальных. Неизвестный формат страницы считается ошибкой, а не нулём объявлений.

Первый этап — MacBook на Apple Silicon и Neo, поддерживаемые текущей нормализацией проекта. Для другой техники надо добавить собственную схему конфигурации и эталонные тесты; универсальное распознавание любой техники сейчас не заявляется.

## Математическая модель v1

Версия: `seller-robust-logprice-v1`. Это объяснимая статистическая модель и набор бизнес-правил. Обученная или откалиброванная вероятность достоверности не заявляется.

1. **Сопоставимость.** Группа: модель, чип, экран, RAM, SSD, цвет. Известные противоречия CPU/GPU исключают сравнение. Неизвестные CPU/GPU/клавиатура уменьшают полноту доказательств; они не дорисовываются.
2. **Независимость.** Один профиль продавца — одна единица веса. Цена профиля — медиана его различных цен в группе. Повтор той же цены не меняет медиану. Сайт магазина и его профиль объединяются только по проверенному соответствию ID → магазин, а не похожему имени. Для оценки объявления все предложения его продавца исключаются (leave-one-seller-out). Неизвестные связи между разными профилями остаются ограничением.
3. **Устойчивый центр.** Для независимых цен `x = ln(price)`; начальный центр — медиана, масштаб `s = max(0.03, 1.4826 × median(|x − median(x)|))`. Huber-вес `min(1, 1.345/|z|)` уменьшает влияние крайних значений. Выполняется до 12 итераций взвешенного центра.
4. **Свежесть и объём информации.** Базовый вес `exp(−ageHours/6)`. Эффективное число источников по Kish: `(Σw)²/Σw²`; информация ограничивается также `Σw`, чтобы одинаково устаревшие цены не сохраняли прежнюю уверенность. Из ориентира исключаются цены старше четырёх часов, отсутствующие товары и явные проблемы.
5. **Объединение каналов.** Магазины НН и продавцы Авито дают отдельные устойчивые оценки. Магазинный центр задаёт ориентир с добавочной дисперсией `0.08²` в логарифмах для различий каналов. Центры объединяются пропорционально обратной дисперсии: `V = 1/(1/Vshops + 1/Vavito)`, `μ = V(μshops/Vshops + μavito/Vavito)`. При отсутствии одного канала используется второй. Разброс предложения `sqrt(s²+V)` учитывает и рыночный разброс, и неопределённость центра.
6. **Диапазон.** В интерфейс передаётся `exp(μ ± 1.96 × sqrt(s²+V))`. Это диапазон выбранной модели, не эмпирически доказанный 95%-й интервал для сделок. При малой выборке Trust ограничен средним.
7. **Скоринг.** Исходный балл: `100 × (0.40 × priceFit + 0.25 × freshness + 0.25 × support + 0.10 × completeness)`, где `priceFit=exp(−0.5 × max(0,|z|−1)²)`, `support=1−exp(−information/3)`. Это инженерные коэффициенты v1, а не обученные веса.
8. **Жёсткие причины низкого Trust.** Цена более чем на 5% ниже среднего независимых магазинов (минимум два); при отсутствии такого ориентира — ниже устойчивого центра минимум трёх сторонних продавцов. Также: более дешёвый цвет у одного продавца, заведомо низкий Trust связанного магазина, |z|>3.5, проверка старше четырёх часов, резкий переход относительно предыдущей цены, предзаказ или условная цена в описании. Эти признаки ограничивают балл 49 и дают читаемую причину.
9. **Порядок.** Сначала группа Trust high/medium/low. Внутри — возрастающая `price / sqrt(max(0.1, score/100))`, затем стабильный ID. Это позволяет сравнивать цену с неопределённостью, не поднимать подозрительно дешёвое объявление выше проверенного.

### Что нужно для калибровки

Собрать настоящие карточки и вручную проверить минимум несколько сотен примеров с разными моделями и продавцами: состояние, точную комплектацию, продавца, наличие, безусловную цену. Разделять обучение/проверку по продавцам и времени, иначе повторы создадут ложное качество. Измерять точность допуска в таблицу, долю карантина, ошибки конфигурации, полноту сбора и устойчивость top-k. После накопления исходов можно калибровать скоринг; до этого балл не называется вероятностью.

## Запуск и эксплуатационные границы

`npm run collect:avito` без настройки транспорта записывает `not_configured`, без запросов в сеть. На dev установлены сервис и почасовой таймер из `deploy/avito/`; `/etc/mac-price-radar/avito-dev.env` включает `AVITO_TRANSPORT=http`. Worker сохраняет промежуточный срез после первой карточки и каждых 25 проверок. При отказе доступа уже разобранные карточки сохраняются частичным срезом. Общий почасовой сбор импортирует этот срез в таблицу; незавершённый обход не снимает исчезнувшие объявления.

HTTP-транспорт используется для обычных запросов с явным `AVITO_TRANSPORT=http`. Он не получает cookie из браузера, не меняет IP и не решает CAPTCHA. Ограничение 403/429 прекращает запросы и устанавливает `retryAfter` через шесть часов. Почасовые срабатывания таймера до этого времени завершаются без сетевого запроса.

Полный проход 1500 карточек + примерно 30 страниц при интервале минимум 2 секунды занимает теоретически от 51 минуты, не считая задержек сверх интервала. Лимит процесса — 55 минут. Реальную почасовую пропускную способность ещё нужно измерить.

`queue.json` сохраняет время каждой попытки разбора и последнего успешного получения карточки. Каждый запуск заново проверяет выдачу, затем сначала посещает ещё не проверенные ID, после — проверенные наиболее давно. При одинаковом времени сохраняется порядок выдачи с приоритетом НН. Поэтому после прерывания первые объявления не занимают бюджет следующего запуска повторно. Очередь привязана к URL поиска, содержит только служебные даты и не служит источником цен или ссылок для запросов. Используются URL из текущей выдачи. На блокировке посещение прерванной карточки не считается завершённым; шестичасовая пауза сохраняется. При истечении лимита времени уже полученные карточки также сохраняются частичным срезом. Старые наблюдения не копируются в новый срез и не получают новый timestamp. Очередь не устраняет ограничение доступной выдачи в 1500 объявлений и сама по себе не гарантирует проверку каждого объявления раз в час.

Для проверки без сети поддержан `AVITO_CAPTURE_MANIFEST`: JSON с `capturedAt`, `searchUrl` и `pages` (отображение полного URL в относительный путь к HTML). Те же разборщики и фильтры используются в replay. Контрактные примеры в `test/fixtures/avito/` искусственные и не загружаются в рабочую базу.

Критерии полного аудита: настоящая выдача и разные варианты карточек успешно разобраны; проверены продавцы-исключения; полный проход сверил количество; повторный запуск через час сохранил изменения цен; проверены снятие объявления, отказ доступа и восстановление; измерено качество допуска на размеченной выборке. Пока в dev видны отдельные наблюдения и фактический статус неполного сбора. Утренняя диагностическая карточка импортирована в историю с исходным временем и истёкшим сроком проверки; она показывается как старая с низким Trust. Проверка свежести штатных срезов не ослаблялась.
