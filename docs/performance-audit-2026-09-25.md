# Аудит производительности dev.macbookbro.ru — 25 сентября 2026

Изменения опубликованы на dev.macbookbro.ru. Проверены весь действующий путь сбора цен, SQLite, HTTP API, браузерная таблица и настройки Caddy. Сайт заказов и основной домен не менялись.

## Измерения

Измерения API выполнены на самом сервере через loopback. Это время ответа приложения, не полное время загрузки страницы у пользователя. Сетевой путь и запрос пароля могут добавлять задержку.

| Проверка | До | После |
| --- | --- | --- |
| Каталог, обычный запрос приложения | `/api/master`: 399 мс, 6 543 720 байт | `/api/table`: 159 мс при построении, 3–5 мс при повторном запросе; 1 399 887 байт без сжатия |
| Передача каталога с gzip | Сжатие отсутствовало | 167 418 байт через Caddy 2.6.2, около 39 раз меньше старого ответа |
| Повторный неизменившийся каталог | Полный ответ | HTTP 304, без тела |
| Полный сбор десяти источников | Предыдущий запуск: 73,7 с | Первый запуск новой версии: 32,9 с; 10/10 источников — success |
| RifaStore: наблюдения за один сбор | 1 936 | 972; 964 одинаковых повтора исключены |

Время сбора сравнивает два соседних живых запуска, поэтому зависит также от отклика магазинов. Оно не является гарантированной длительностью каждого следующего запуска.

Проверка gzip выполнена отдельным временным Caddy на loopback с теми же `encode zstd gzip` и reverse_proxy. На публичном dev проверено наличие обоих кодировщиков и сохранение аутентификации; запрос без пароля получает 401. Полный авторизованный браузерный замер публичного HTTPS не выполнялся: доступная сессия Chrome запросила пароль. Интерфейс проверен в локальном браузере на том же коде.

## Охват сборщиков

- BigGeek: существующие URL и справочник, ограничение три карточки одновременно, контроль покрытия и сохранение прежней цены при ошибке.
- Айфория: WooCommerce API, проверка числа категорий, страниц и карточек, повтор временных HTTP-ошибок.
- Technichno и iMobile: очереди обнаружения карточек и вариантов, не более трёх страниц одновременно внутри источника, контроль неполного обхода.
- ReSale, Apple Store и Rebro: сохранены проверки пагинации, итогового количества товаров, вариантов и условий цены.
- RifaStore: проверены поиск категорий, пагинация, извлечение цены, контроль покрытия; добавлено удаление одинаковых повторов перед записью.
- BSA и Дима: локальный кэш Telegram, отбор датированных прайсов, идентификация вариантов; сетевой webhook не запускается при чтении страницы.
- Общие модули: нормализация, проверки качества, каталог, история SQLite, экспорт, серверное расписание и блокировка сборщика.
- Служебные backup/export/sync и старый `src/cli.ts` не участвуют в загрузке dev. Действующая точка запуска — `scripts/server.mjs`, сборщик — `scripts/build-data.mjs`.

## Публикация и восстановление

Сервис: `mac-price-radar@dev`, каталог `/srv/mac-price-radar/dev`, порт 4174.
Резервная копия перед публикацией: `/srv/mac-price-radar/releases/dev-performance-20260925/backup/` — согласованная SQLite с манифестом, исходный код и прежний Caddyfile.

Изменения Caddy ограничены строкой `encode zstd gzip` в блоке `dev.macbookbro.ru`. Пароли, правила webhook и конфигурации остальных доменов не менялись. Проверка `caddy validate` прошла. При публикации использовался автоматический откат при неуспешной проверке приложения.

Для возврата поведения приложения достаточно восстановить `scripts/` и `web/` из `backup/code.tar`, вернуть владельца `radar:radar` и перезапустить только dev-сервис. Восстанавливать старую базу ради отката кода не требуется: добавленный индекс обратно совместим. Восстановление базы из копии потеряло бы более поздние наблюдения и без отдельной причины не нужно.

## Границы результата
