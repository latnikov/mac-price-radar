# Mac Price Radar — единая таблица цен

Одна большая таблица публичных цен российских магазинов с поиском и фильтрами. Конфигурации MacBook расположены в строках, магазины — в столбцах. Закупки, себестоимость, заказы и другие бизнес-функции будут надстраиваться позже.

Исходные бизнес-требования: [requirements.md](requirements.md). Текущий приоритет и состояние серверных модулей: [IMPLEMENTATION.md](IMPLEMENTATION.md).

Отдельный сайт заказов «Макбучная» для `order.macbookbro.ru`: [описание и запуск](order-site/README.md). Локальный просмотр: `npm run dev:orders`, проверки: `npm run test:orders`. Сервис и база заказов отделены от парсера цен.

## Запуск

Требуется Node.js 22.13+ с `node:sqlite` (проверено на Node 24).

```bash
npm install
npm run build:data
npm run dev
```

Откройте <http://127.0.0.1:4173/web/>. Для текущего компьютера без Node в PATH:

```bash
/Users/max/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/build-data.mjs
/Users/max/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/server.mjs
```

Первый `build:data` сохраняет исходный `data/cheapest.json` в `data/private/backups/` и переносит реальные наблюдения в `data/private/master.sqlite`. Демонстрационные примеры исключаются. Без `LIVE=1` сеть не опрашивается: пересчитывается представление сохранённой базы.

## Работа с таблицей

- Выбор модели, процессора и конфигурации кнопками в стиле сайта заказов. Поиск и кнопка ручного обновления убраны.
- При открытии показаны 50 конфигураций новых Mac mini и Mac Studio из Excel: исходные цены и составляющие в USD. Это датированный прайс под заказ, а не наблюдение наличия магазина.
- Фильтры по модели, чипу, RAM, SSD, цвету, магазину, наличию и диапазону цены.
- Сортировка по модели, цене или времени проверки.
- Все подходящие строки на одной странице, закреплённые заголовки и первый столбец.
- В первой закреплённой колонке — модель и компактные ярлыки диагонали, чипа, CPU/GPU, RAM, SSD и цвета. В ячейке магазина — минимальная цена; нажатие на ценник сразу открывает страницу товара.
- «Лучшая цена» автоматически выбирается из цен, показанных в магазинных колонках, без отдельного статуса проверки.
- Ритейл-аналитика показывает минимальную текущую закупку, среднюю доверенную цену магазинов Нижнего Новгорода, разницу в рублях и процентах, а также рекомендованную цену на 500 ₽ ниже минимального доверенного предложения НН.
- Для каждого магазина НН цена более чем на 5% ниже среднего ориентира помечается как `Trust: низкий`. Та же плашка ставится более дешёвому цвету, если в одном магазине одинаковая конфигурация продаётся по разным ценам в зависимости от цвета. Такие цены остаются видимыми, но не влияют на итоговую среднюю и рекомендацию. ReSale имеет низкий Trust по умолчанию.
- Кнопка «Скачать срез JSON» сохраняет предложения с учётом выбранных фильтров.

Интерфейс `dev.macbookbro.ru` выдержан в едином ретро-HTML стиле и везде использует Times. Сайт имеет мобильную CTA, favicon-набор, Open Graph-картинку, `robots.txt`, `sitemap.xml`, свою 404-страницу и обезличенную first-party аналитику. События без IP-адресов пишутся в закрытый `data/private/analytics.ndjson` и не попадают в репозиторий.

Строка объединяет только сопоставимую аппаратную конфигурацию: модель, диагональ, чип, CPU/GPU, RAM, SSD и цвет. Клавиатура и регион сохраняются внутри магазинной ячейки; неизвестные CPU/GPU показаны явно и не объединяются с подтверждённой конфигурацией.

Все цены в таблице — в рублях. Отсутствие валюты в разметке магазина не отклоняет цену. Старые цены остаются видимыми с отметкой «Старая проверка» после четырёх часов. Неизвестное наличие показывается отдельно. Время каждой цены отображается в часовом поясе браузера.

## Сбор цен

Подключены BigGeek, Айфория, RifaStore, Technichno, iMobile, ReSale, Apple Store Нижний Новгород, Rebro Нижний Новгород, Madstore Нижний Новгород и Telegram-источник BSA (`@BigSaleApple`). iMobile обходится от каталога `/mac` до карточек MacBook и публикует каждый выбираемый вариант отдельно по цене без карты лояльности. ReSale читает публичный каталог Tilda с сайта `resale52.ru`, публикует каждый вариант памяти и цвета отдельно и помечает цены как розничные за наличный расчёт. Apple Store обходит все страницы каталога `nn.stores-apple.com`, проверяет полноту по общему числу карточек и публикует обычную розничную цену; более низкая условная цена при покупке гарантии не используется. Rebro обходит все страницы `nn.rebro-store.ru/catalog/mac/`, сверяет число карточек с итогом каталога и публикует текущие цены доступных MacBook и iMac, не принимая зачёркнутую обычную цену за актуальную. Madstore начинает с `/macbook`, обнаруживает все связанные категории и секции публичного Tilda-каталога, проверяет пагинацию и дубли, а в таблицу публикует явно обозначенную цену при оплате наличными. BSA-коннектор принимает через Bot API посты канала и пересланные из него сообщения, хранит последний кэш вне публичных файлов и разбирает датированные прайс-листы MacBook Air, Neo и Pro. Используются только прайсы с датой не раньше текущего дня по Москве; веб-страница `t.me` и пользовательская MTProto-сессия не используются.

Telegram Business Connection даёт боту доступ только к выбранным личным чатам бизнес-аккаунта и не даёт доступ к подпискам аккаунта на каналы. Поэтому полностью автоматические `channel_post` от `@BigSaleApple` возможны только если владелец канала добавит бота в канал. Без этого официальный Bot API получает BSA-пост только после его пересылки боту. Bot API не предоставляет запрос истории чатов.

Токен хранится только на сервере в закрытом файле вне репозитория:

```bash
TELEGRAM_BUSINESS_BOT_TOKEN=123456:secret
TELEGRAM_BSA_CHANNEL=BigSaleApple
TELEGRAM_BUSINESS_WEBHOOK_SECRET=random-secret
TELEGRAM_BUSINESS_WEBHOOK_IP=135.106.220.39
```

Сервису нужно передать этот файл как `EnvironmentFile`. Его права должны оставаться `0600`; содержимое нельзя коммитить или выводить в логи. В dev используется защищённый webhook `https://dev.macbookbro.ru/api/telegram/bsa-webhook`. `TELEGRAM_BUSINESS_WEBHOOK_IP` необязателен и привязывает доставку Telegram к конкретному IPv4. Если webhook-секрет не задан, сервер использует long polling как резервный режим. Для разовой проверки polling без запуска веб-сервера доступен `npm run telegram:poll`.

Если хостинг не может напрямую соединиться с Telegram, `apps-script/telegram-relay.gs` работает как минутный polling-релей. В Script Properties задаются `TELEGRAM_BOT_TOKEN`, `DEV_WEBHOOK_URL` и `DEV_WEBHOOK_SECRET`, после чего один раз запускается `installTelegramPoller`. Релей забирает очередь через Bot API, пересылает обновление в защищённый dev webhook и только после успешного ответа сохраняет следующий `TELEGRAM_LAST_UPDATE_ID`; поэтому недоставленное сообщение не подтверждается и будет повторено.

Сервер автоматически собирает цены и ассортимент всех подключённых источников при запуске и каждый час. Открытый браузер не требуется. Таймер использует общую блокировку с Telegram-обновлениями. `AUTO_REFRESH_INTERVAL_MS=0` отключает встроенное расписание для сред с внешним таймером. В закупке дата прайса показывается как «Сегодняшний ценник», «Вчерашний ценник» или конкретная дата. Ручной служебный запуск:

```bash
LIVE=1 RETAILER=Technichno npm run build:data
LIVE=1 RETAILER=ReSale npm run build:data
LIVE=1 RETAILER='Apple Store' npm run build:data
LIVE=1 RETAILER=Rebro npm run build:data
LIVE=1 RETAILER=Madstore npm run build:data
LIVE=1 npm run build:data
```

Состояние обновления показывает текущий источник и число завершённых источников. Отказ или неполный сбор одного магазина не удаляет сохранённые цены. Блокировка предотвращает одновременный запуск двух сборщиков; сетевые запросы и весь процесс ограничены таймаутами.

## Хранение и резервная копия

Источник истины — локальная SQLite с историей наблюдений. JSON является производным снимком. Неоднозначные цены и конфликты характеристик сохраняются для проверки; пропавшая из частичного сбора карточка не считается отсутствующей в продаже.

```bash
npm run backup
node scripts/backup.mjs /path/to/backup-directory
```

Копия содержит SQLite, каталог, требования и контрольные суммы. По умолчанию она сохраняется в `data/private/backups/`. Внешняя копия и регулярное расписание пока не настроены.

Сервер слушает `127.0.0.1`, раздаёт только разрешённые файлы и API. SQLite и закрытые данные из `data/private/` не публикуются. Текущий режим рассчитан на одного локального пользователя.

Служебная публичная выгрузка `npm run export:public` отделена от рабочей таблицы и содержит только утверждённые цены из отдельного контракта. Сейчас таких решений нет, поэтому она пуста. GitHub Pages не получает локальную мастер-базу. Внешняя публикация таблицы и Google Sheets в этой итерации не подключались.

## Проверки

```bash
npm test
npm run typecheck
```

Проверяются разбор и сопоставление предложений, сбои и повторные сборы, история, восстановление базы и изоляция публичного экспорта. Возможности служебных модулей, ещё не выведенные в таблицу, описаны отдельно в `IMPLEMENTATION.md`.

## Производительность dev

Результаты аудита и публикации 25.09.2026: [измерения, изменения и восстановление](docs/performance-audit-2026-09-25.md).

Браузер использует компактный `/api/table`; полный `/api/master` загружается при экспорте. Стартовый desktop-прайс не ждёт каталог магазинов. Готовые ответы кэшируются с проверкой изменений SQLite, файлы и снимки поддерживают ETag/304. На dev в Caddy включены `encode zstd gzip`. Фоновый сбор обновляет до трёх разных источников одновременно, сохраняя прежние ограничения внутри каждого магазина и общую блокировку.
