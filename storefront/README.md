# Макбучная: магазин и CRM

Магазин: `https://macbookbro.ru/`, управление: `/crm`. Сначала карточка публикуется на сайте, затем попадает в выбранные каналы. Данные конкурентов сами не создают ассортимент.

## Запуск

Node >=22.13 (production проверен на Node 24). Дополнительные зависимости не нужны.

```sh
STORE_ADMIN_PASSWORD='local-preview-password-only' STORE_DEV_FILE=/absolute/path/to/table.json npm run dev:shop
npm run test:shop
```

Открыть `http://127.0.0.1:4190/crm`. JSON источника: `{ "offers": [...] }`, как `/api/table` парсера. Для production использовать пример `deploy/shop.env.example`; секреты хранить вне репозитория в файле окружения с правами 600. Процесс слушает только loopback.

## Что работает

- Черновики и публикация карточек, сопоставление dev, до 6 фотографий, индивидуальные экземпляры.
- Расчёт через тот же `web/retail-analytics.js`, что в dev: колонка «Рекоменд. цена», без повторного вычитания 500 ₽. Проверяются Trust, собственные источники, возраст и неоднозначность конфигурации. Профиль — весь каталог dev без пользовательских фильтров.
- Отсутствующая/просроченная цена заменяется запросом стоимости. В каналы нулевая или просроченная цена не отправляется. Повтор импорта не обновляет возраст наблюдения.
- Корзина (4 разных позиции), заказ без JavaScript, повторное подтверждение при изменении цены. Принятые цена, характеристики и сопоставление учёта фиксируются в заказе. Повтор отправки не создаёт дубль.
- CRM: заказы, клиенты, статусы, заметки, очередь обмена. Роли владельца и менеджера; менеджер работает с заказами. Это первая версия CRM, отдельные поля задач, сроков, ответственных и платежей ещё не реализованы.
- Telegram: создание текста/фото, редактирование той же публикации, закрытие предложения. При неопределённом результате создания — ручная сверка в CRM, без слепого повтора.
- МойСклад: запись розничной цены в указанный тип цены существующего товара/модификации; создание заказа покупателя по сохранённой цене и стабильному externalCode. Требуются точные UUID, организация и контрагент. Обратного импорта остатков нет. Автоматические изменения статуса уже созданного документа не реализованы.
- Яндекс: YML по закрытой ссылке, доступной владельцу в `/crm/channels`; карточка компании 65600128575. Ссылку нужно подключить в Яндекс Бизнесе. Получение файла не считается подтверждением публикации.
- Авито: подготовлен XML автозагрузки; рабочая выдача выключена до проверки категории, обязательных полей и прав аккаунта. OAuth API и получение отчётов Авито пока не реализованы. Нельзя считать Авито подключённым только по наличию XML.

## Лёгкая витрина и защита

Обычные страницы содержат только HTML и встроенные стили, без JavaScript, внешних шрифтов и автоматически загружаемых фото. Тесты проверяют размер <14 000 байт до сжатия, включая длинный текст и HTML-экранирование. Фото открываются отдельной страницей и не входят в обещание 14 КБ.

На публичных страницах нет складских статусов, закупок, источников цены или ключей. CRM защищена, формы проверяют Origin и CSRF, сессии HttpOnly/SameSite, заказы доступны только своей сессии. По умолчанию 90 запросов в минуту на IP, 30 операций записи, 8 попыток входа за 15 минут. IP хранится в виде HMAC. Смена cookie не сбрасывает ограничение. Это снижает массовый сбор, но не исключает медленный распределённый парсинг публичной цены.

## Подключение площадок

1. Заполнить серверные параметры конкретного аккаунта. Не переиспользовать бота чтения сообщений для отправки без проверки его назначения и прав.
2. Добавить собственный компьютер, проверить совпадение всех характеристик dev и выбрать нужные каналы.
3. Проверить создание, изменение цены, снятие, повтор и ошибку доступа на согласованной тестовой позиции.
4. Яндекс: в кабинете нужной компании «О компании → Товары и услуги → Источник → YML-фид» указать закрытую ссылку из CRM. Подтвердить результат в Картах отдельно.
5. Авито: получить требования автозагрузки для категории/тарифа, проверить XML `/crm/exports/avito.xml`, затем разрешить выдачу. Переданный ранее в переписке секрет не сохранён в коде; для рабочего подключения рекомендуется новый серверный секрет.

Официальные источники: [Яндекс Бизнес](https://yandex.ru/support/business-priority/ru/manage/price-list), [Telegram](https://core.telegram.org/bots/api), [МойСклад](https://dev.moysklad.ru/), [Авито](https://developers.avito.ru/api-catalog).

## Установка и откат

Поставляются каталог `storefront` и файл `web/retail-analytics.js`. Сервис `deploy/macbookbro-shop.service` использует `/srv/macbookbro-shop`, данные `/var/lib/macbookbro-shop`, настройки `/etc/macbookbro-shop.env`. Старый сервис заказов остаётся на `order.macbookbro.ru`; его формы, API и сохранённые заказы не переносятся и не удаляются.

Перед сменой маршрута сохранить Caddyfile и проверить новую конфигурацию. CRM может использовать существующий вход Caddy: секрет proxy-header добавляется только после basic auth; клиентский заголовок на всех остальных маршрутах удаляется. Основной домен направляется на 4190, старый защищённый парсер сохраняется под `/prices/`.

Перед изменением сервиса сделать согласованную копию SQLite:

```sh
STORE_DB=/var/lib/macbookbro-shop/shop.sqlite STORE_MEDIA_DIR=/var/lib/macbookbro-shop/media node storefront/backup.mjs /private/backup/new-directory
```

Для восстановления остановить магазин, сохранить текущую БД отдельно, заменить БД и media проверенной копией, убрать относящиеся к старой БД WAL/SHM, выставить права `radar:radar`, запустить. Проверить `PRAGMA integrity_check`, число товаров/заказов и один сохранённый заказ. Копию хранить вне сервера; автоматический внешний архив пока не подключён.

Откат маршрута: восстановить сохранённый Caddyfile, выполнить проверку конфигурации и reload Caddy. Базу магазина сохранять: откат витрины не должен удалять новые заказы.

## Границы запуска

Для наполнения нужны реальные компьютеры владельца. Для коммерческого запуска нужны подтверждённые сведения продавца и условия покупки, аккаунты интеграций и проверка публикаций в них. Эквайринг не подключён: форма принимает заказ с дальнейшим подтверждением и оплатой наличными или по счёту. Клиентские уведомления и уведомления менеджера для нового магазина пока не подключены — новые заказы видны в CRM.
