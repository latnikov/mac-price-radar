# Макбучная: витрина, кабинет и CRM

Магазин — https://macbookbro.ru/, управление — /crm. Node 24+, SQLite WAL, HTML/CSS без обязательного JavaScript. Дополнительные npm-зависимости для магазина не нужны.

Единый редизайн витрины, CRM, клиентского/служебного входа и встроенного парсера `/crm/parser/`: [устройство, проверки и публикация](../docs/redesign-2026-10-01.md). Публичный `/order/` сохраняет прежнее оформление.

## Запуск

Источник цен — JSON с массивом offers, как /api/table dev. Настройки production — [shop.env.example](deploy/shop.env.example); секреты остаются вне репозитория. Процесс слушает loopback. CRM поддерживает владельца и менеджера, CSRF, Origin, смену сессии после входа и ограничение попыток. Локально: npm run dev:shop; тесты: npm run test:shop.

## Каталог

Реестр Apple проверен 1 октября 2026: Neo A18 Pro, Air M5, Pro M5/M5 Pro/M5 Max. Только новые компьютеры, корректные размеры, память, накопитель, цвет и сочетания ядер. Обозначения прайса 1000/2000 ГБ принимаются как 1/2 ТБ; исходный ключ расчёта dev сохраняется.

Владелец запускает импорт в /crm/products. STORE_AUTO_CATALOG=1 включает обновление при получении цен. Стабильные ID, без дублей и перепубликации после ручного снятия. Цена по формуле «Рекоменд. цена» dev без второй скидки. Просроченные/неоднозначные цены заменяются запросом стоимости; б/у источник не обновляет цену новой карточки. Наличие конкурента не означает наличие магазина. Исходящие каналы по умолчанию выключены.

Карточки поддерживают до шести фото и точное сопоставление товара/модификации МойСклад. Обычная публичная страница вместе со стилями — менее 14 000 байт до сжатия; внешние шрифты, скрипты и автоматически загружаемые фото отсутствуют. Фото открываются отдельно по выбору покупателя.

## Кабинет и доставка

Регистрация требует email, российский телефон и пароль от 10 символов. Вход по email либо телефону. Пароли защищены scrypt с индивидуальной солью. Телефон без SMS не считается подтверждённым. Совпадение телефона/email не открывает старые заказы: привязка из своей гостевой сессии или при оформлении из аккаунта. Заказы, доставка, трек-номер и обращения доступны в кабинете. Ответ менеджера появляется там же.

Корзина — до четырёх разных позиций. Заказ без регистрации/JavaScript, с неизменным первоначальным снимком характеристик и цен, защищён от повторной отправки. Самовывоз — 0 ₽; доставка по Нижнему Новгороду и России неизвестна до согласования. Менеджер предлагает цену, срок и адрес, покупатель подтверждает предложение. При изменении условий требуется новое подтверждение. Оплата после подтверждения наличными либо по счёту; эквайринг не подключён.

Восстановление по почте требует STORE_MAIL_WEBHOOK_URL и защищённого токена. HTTPS endpoint принимает JSON {to,subject,text}, Bearer и Idempotency-Key. Одноразовая ссылка действует 20 минут, сброс отзывает остальные сессии. Истёкшие и отправленные секреты удаляются из очереди. Без почтового провайдера восстановление требует обращения в магазин.

## CRM и данные

Клиенты, сегменты, диалоги, сделки, ответственные, следующие действия, причины потери, задачи, заказы, доставка и обращения. Менеджер работает с покупателями; каталог, подключения и себестоимость доступны владельцу. Закуп разделён на FACT/MANUAL/ESTIMATE/UNKNOWN. Неизвестный закуп не равен нулю. Ожидаемый вклад заказа не выдаётся за признанную прибыль или полный финансовый P&L.

/crm/integrations показывает фактический статус источников, /crm/stock — отдельный текущий снимок остатков МойСклад, /crm/accounting — контрагентов, товары, модификации, заказы, приёмки, отгрузки, возвраты, оприходования, списания и входящие платежи. Финансовые документы — с 1 января 2026. Сбой пагинации не сдвигает курсор; успешные страницы сохраняются. Повтор по стабильным ID не создаёт дубли и не перезаписывает локальные заметки.

Авито читается по STORE_DATA_SYNC_INTERVAL_MS (на сервере — раз в пять минут) по раздельным ключам двух профилей. Полнота истории зависит от тарифа и пагинации и отмечается явно. Импорт не помечает сообщения прочитанными. Отправка из CRM выключена до подтверждения профиля/тарифа. Неизвестный результат отправки требует сверки и не повторяется автоматически. Файлы вложений не импортируются.

Telegram работает через архив Desktop и Business-бота. API ID/Hash для этого варианта не нужны. Архив импортируется командой `node --env-file=/private/config.env scripts/telegram-crm-import.mjs /private/result.json`. Требуется полный JSON рабочего @macbookbro и совпадение STORE_TELEGRAM_ACCOUNT_ID. Личные диалоги создаются по числовым ID, группы/каналы/боты исключаются. Сервисные события сохранены отдельно по типу; статус прочтения архива неизвестен. Повторная загрузка не заменяет живые изменения и удаления. Архив хранит дату охвата, а не обещание полной облачной истории.

Для новых сообщений: STORE_CRM_TELEGRAM_BOT_TOKEN (либо _FILE), STORE_CRM_TELEGRAM_EXPECTED_BOT=mbroadmin_bot и STORE_TELEGRAM_ACCOUNT_ID. В BotFather включить Business/Secretary Mode, затем в рабочем аккаунте подключить бота и разрешённые диалоги. Бот проверяется по username и неизменному ID. Чужие аккаунты исключаются. Существующий webhook не удаляется: подключение требует отдельного решения владельца. Polling получает события раз в 5 секунд и сохраняет их перед подтверждением offset. Ошибка отдельного события не блокирует остальные; повтор не создаёт дубли и не восстанавливает более старую версию сообщения. При недоступности узла из DNS можно задать STORE_TELEGRAM_API_IPV4 после проверки HTTPS-сертификата api.telegram.org с сервера. Это прямое TLS-соединение к Telegram с обязательной проверкой сертификата, без стороннего посредника. Исходящие ответы разрешаются отдельно STORE_TELEGRAM_SEND_ENABLED=1, требуют прав соединения и входящего сообщения клиента за последние 24 часа. Перед отправкой права перепроверяются; автоматических ответов нет.

/crm/desk — единое рабочее место с тремя колонками: поиск диалогов, переписка, клиент. /crm/contacts — каталог контактов с поиском по кириллице и страницами. Архивные контакты изначально не классифицированы, предполагаемые сегменты явно помечены. Сопоставление с существующим контрагентом выполняет менеджер вручную; переносится только связь выбранного диалога, не права личного кабинета. Заметки и сделки исходной карточки сохраняются. /crm/sales показывает этапы и отдельные суммы проведённых документов с 01.01.2026. Возвраты вычитаются, валютные суммы не конвертируются по сегодняшнему курсу. Один документ связан максимум с одной сделкой. История этапов и напоминания работают независимо от финансового признания; даты без часового пояса в CRM трактуются как московское время.

Валюты, финансовые документы 2026 года и остатки обновляются полным снимком, поэтому удалённые документы исчезают после успешного чтения всех страниц. Контрагенты, товары и модификации читаются по updated. При частичном сбое прежние записи остаются с явным статусом неполноты. Для редких удалений справочника нужен повторный полный импорт. Прибыль по этим данным автоматически не рассчитывается.

## Исходящий обмен

Заказ МойСклад использует принятые условия и стабильный externalCode, точное сопоставление товаров и отдельного контрагента клиента. Несогласованную доставку отправить нельзя. Платная доставка требует UUID услуги, иначе очередь блокируется с объяснением. Существующие документы автоматически не переписываются. Неопределённое создание требует сверки, слепого повтора нет.

Telegram-канал, YML Яндекс Бизнес и XML Авито сохраняют механизмы публикации после сайта. Получение выгрузки не означает публикацию на площадке. XML Авито выключен до проверки формата/тарифа. Публикации товаров не содержат контактов покупателей.

## Обновление и откат

Релиз: storefront, package.json с type=module, совместимые web/retail-analytics.js, web/price-table.js и web/avito-columns.js. На сервере выполнить python3 storefront/deploy/update.py /absolute/release/path. Сохраняются код, закрытые настройки, согласованный снимок БД и фото. При ошибке возвращается прежний код и сохраняются данные заказов. Caddy и соседние окружения не меняются. Для первого подключения CRM можно передать два дополнительных аргумента: закрытый JSON с разрешёнными ключами окружения и gzip-архив Telegram JSON. Исходные настройки сохраняются до замены, импорт проходит при остановленном сервисе; проверяются контрольные суммы неизменяемых снимков заказов, целостность БД и внешние ключи. Закрытые файлы не входят в Git-релиз.

Отдельный архив: STORE_DB=/var/lib/macbookbro-shop/shop.sqlite STORE_MEDIA_DIR=/var/lib/macbookbro-shop/media node storefront/backup.mjs /private/backup/new-directory. Копию хранить вне сервера. Восстановление БД требует остановки сервиса, сохранения новых заказов отдельно, удаления старых WAL/SHM и проверки integrity_check. Откат кода не должен удалять принятые после релиза заказы.
